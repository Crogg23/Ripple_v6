Verified during the 2026-07-27 full-warehouse pattern sweep (`reports/pattern_sweep_2026-07-27.md`). Four trap classes that keep recurring:

1. **Snowflake `TRY_TO_DATE` on `YYYYMMDD` text parses as epoch seconds** — every date collapses to ~1970 and joins silently match everything. Two agents hit this independently. Always pass an explicit format: `TRY_TO_DATE(col,'YYYYMMDD')`.
2. **Suspiciously round row counts = loader truncation caps, not universes.** Known instances: ~60 RAW tables at exactly 500,000 (bulk-discover cap), FED_SAM_EXCLUSIONS at 9,000 (API cap — the real debarment universe is ~100k+), FED_USASPENDING_CONTRACTS_FULL at exactly 20,000,000, USASpending assistance with five years at exactly 1,000,000 each, FED_CMS_OPEN_PAYMENTS_2022 at exactly 13,250,000. Check for round counts before trusting any table as a universe (see [[bridge-fuel-reality]] for the masked-key cousin of this trap).
3. **Quote-corrupted CSV text kills typed mart columns silently.** MSHA raw kept literal quote chars (`"Y"`, `"FATALITY"`), so every dbt boolean/date cast returns FALSE/NULL — the marts reported zero mine fatalities while 1,208 exist. If a mart boolean is 100% one value, sample the raw text for embedded quotes.
4. **`success` in INGEST_RUNS does not mean sane.** The density gate checks row counts, not column alignment: a zip-ingested-as-CSV OSHA load (5.2M rows, ~100% column-shifted) and six <1%-of-universe API stubs (CFPB 500 rows vs 17M) all logged success. Row-count-vs-registry-VOLUME and column-sanity checks are the missing controls.
5. **Sorted-load + row cap = truncated KEY SPACE, which fakes disjoint joins** (found 2026-08-05 coverage sweep, `outputs/coverage_sweep_findings_2026-08-05.md`). `FED_IRS_AUTO_REVOCATIONS` (500k cap) was loaded in EIN order: max EIN `454595836` — the top ~55% of the EIN space never landed, so a full join against Form 5500 returned only 10 matches on a supposedly verified edge. Worse than the rate-understatement cap trap: it makes real joins measure as zero. Before trusting any join touching a capped table, check MIN/MAX of its key column spans the full key space. 35 landing tables sit at exactly 500k.
6. **Sentinel key values beyond blanks:** DOCKET columns in FED_MSHA_VIOLATIONS / FED_SCDB / FED_OYEZ / FED_FEDERAL_REGISTER_DOCUMENTS are dominated by literal `'0'`; LEIE NPI is 90% literal `'0000000000'`; NPPES `OTHER_PROVIDER_IDENTIFIER_5..36` and `PROVIDER_LICENSE_NUMBER_5..15` are ≤0.01% filled; `FED_CMS_FACILITY_AFFILIATION.FACILITY_TYPE_CERTIFICATION_NUMBER` has 188 non-blank of 2.26M. `FED_DOL_FORM5500.PLAN_NUM` is 0% filled despite being the obvious-looking ERISA plan-number column — the real one is `SPONS_DFE_PN` (100% filled). Found 2026-08-05, see [[exhaustive-id-sweep-2026-08-05]].
7. **Raw schema drift breaks the checked-in dbt model, and a stale `SELECT * FROM raw` stopgap under a personal schema (e.g. `DBT_CROGERS`) silently papers over it.** Confirmed twice in the 2026-07-28 repair pass: `FED_CFPB_COMPLAINTS` was reloaded with CFPB's bulk-CSV headers instead of the API's snake_case fields, and `INTL_IE_CRO` was reloaded under a wholly different column set (`COMPANY_NUM`/`COMPANY_STATUS_CODE`/... vs the model's `COMPANY_ID`/`COMPANY_STATUS`/...). In both cases the checked-in staging model errored on any real rebuild, but a table sitting at the mart's expected physical location (same schema/name) had identical columns to the *raw* table — i.e. someone had manually dumped raw straight into the mart slot as a stopgap. Looks like a working mart (right name, right location, plausible row count) until you check its actual column names against the model that's supposed to produce it.

**Why:** every one of these produced a plausible-looking false anomaly or hid a real one during the sweep; they will bite any future hunt or mart build that skips the check.
**How to apply:** before trusting any table — COUNT vs known universe, check for round counts, sample raw text of dead-looking typed columns, never treat ingest status as data validation, and before rebuilding a broken mart check whether its current physical columns actually match the raw source (a passthrough stopgap) rather than the model's declared output.
