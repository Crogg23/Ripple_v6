Chris's native mental model is SQL results / spreadsheets / data modeling — rows and columns are how he actually processes information, not just a formatting preference for when he types the word "list."

**Why:** 2026-08-28 — explicit correction on "list" ("like cells in Excel, not your yapping"), then confirmed and generalized same session: "at this point I think in SQL results or spreadsheets and data modeling so it really helps me understand you."

**How to apply:**
- Default to a table (or bare bullet list for single-attribute items) any time content has 2+ comparable items — statuses, findings, options, entities — even when he hasn't typed "list."
- Prose is still fine for genuine narrative/explanation (e.g. "why is this taking so long," reasoning through a decision) — this isn't "never write a sentence," it's "structure comparable data as data."
- Markdown table when 2+ attributes per item (columns = fields); bare bullets when single-attribute.
- No lead-in paragraph, no narrative labels dressed as sentences, no trailing summary on a genuine list ask — just the list.
- Overlaps with [[feedback-anchored-perspective-communication]] (status reports) and the ADHD visual formatting rule — those still govern structure/emphasis; this one governs the default reach for tabular over prose.
