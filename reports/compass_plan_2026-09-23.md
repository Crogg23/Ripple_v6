## Traps already on file that the audit must use as expectations

- NPPES EIN column is 100% empty strings. A tag there is a dead link.
- Portal tables cap at 10,000 rows. 169 sit at the cap. Counts are floors.
- Key reach is not a usable join. ZIP tops reach and identifies nothing.
- Single-word name matches are 8% real. ORG_NAME links grade PROBABILISTIC at best.
- EIN and CIK widths differ. Pad EIN to 9, drop 000000000, number the CIK.
- Owner flag and CHOW flag columns are constants. A tagged flag can hold one value.
- FEC SUB_ID is a per-row record number. The catalog tags it FEC_ID, strong.

## The phases, corrected

### Phase 1 — audit, read-only, one saved script
`scripts/audit_catalog.py`, run from the repo, never a heredoc. Checks:

- **C1 inventory.** Base table vs view. COUNT(*) on the 22 views. Every `__PREV_`, `_BAK_`, `ZZ_`, `_RESTORE_` object.
  Exact duplicates: same column list and same row count. Schema near-duplicates, report only.
- **C2 tag truth.** Run the real tagger over all 20,868 mart columns. Diff against the regex catalog.
  For each tagged column, sample values against the key's format: NPI 10 digits with Luhn check,
  EIN 9 digits, CCN 6 characters, FIPS 5 digits, ZIP 5 digits, CIK numeric, and so on.
  A column that fails format is a wrong tag. Reuse the KEY_VALIDATION row shape.
- **C3 missing tags.** Value-shape scan of untagged columns for NPI, EIN, DEA registration,
  NDC, NAICS, HCPCS, CFDA, CAS. A hit is a column carrying a key nobody tagged.
- **C4 link truth.** Hard IDs only: for each tagged pair, share of A's distinct values found in B.
  Geo keys get fill rate, not pairwise match. Name keys excluded, graded PROBABILISTIC by rule.
- **C5 time.** Which marts have a TIMELINE view, which have dates but no view, and each grain.
- **C6 words.** Per table: has summary, has row meaning, share of columns described, and where from.

Outputs: `audit/catalog_audit_<date>.md` and a TSV. Writing
`LIBRARY_META.AUDIT.CATALOG_AUDIT` is a warehouse write, so it waits for a go.
Then the MAP section goes into `score_warehouse.py`, so the grade is a command.
