| OSHA inspections re-pull | `FED_DOL_OSHA_INSPECTIONS` | **error** | 4,110,000 (3,695,000 distinct) | unknown | unknown | 2026-08-23 16:03 (~39h) |

Findings:
- **No silent drift** — every live count matched its own checkpoint file exactly
  for LDA, FEMA IA, and USASpending. The gap is real: these processes just
  stopped running, not a logging lie.
- **SAM exclusions is actually finished**, not mid-load — the extract-file
  fallback (switched to after the paged API got throttled) landed clean at
  168,328 rows, above its own 160k quality floor. A 10,000-row orphan table
  from the abandoned API attempt is still sitting around and should be dropped
  once staging is confirmed pointed at the `_R2` table.
- **FEMA IA** died on repeated FEMA.gov connection resets after 10 retries —
  looks like server-side flakiness, not a bug in the loader. Resumable as-is.
- **USASpending contracts re-pull** stopped clean with zero error in the log —
  looks externally interrupted (Ctrl-C / closed terminal / sleep), not
  crashed. Resumable as-is. **Correction to yesterday's audit**: its own
  `mechanics.md` says this table is "live right now... still growing" — that
  line is now stale; it has not grown since that audit was written.
- **Senate LDA** stopped with no crash trace at all (no dedicated log file
  exists for this loader). Years done are non-contiguous (1999-2001, then
  2020-2021), meaning two separate partial runs, not one continuous crawl.
  Also: this script loads filing years before it ever touches the
  contributions or lobbyist-registration tables, so those are still fully
  empty.
- **OSHA is the standout problem, and it's new.** The live table carries
  **415,000 duplicate rows (~10% of the table)** — raw count 4.11M vs. 3.695M
  distinct case numbers — almost certainly from an overlapping resume, because
  this loader appends with no dedupe/upsert logic at all. It also crashed on a
  Snowflake upload glitch (`KeyError: 'command'` inside the connector's
  upload step) and has **no quality gate**, unlike the other loaders, so a
  clean finish wouldn't even have caught this. **This needs a code fix
  (dedupe/upsert) before it's resumed, not a blind re-run** — a blind resume
  would very likely add a second layer of duplicates on top of the first.

## 4. dbt test suite

First attempt inside the workflow agent got killed mid-run when the agent's
sandbox tore down (only saw dbt boot: 2199 models, 4,814 data tests found,
zero results logged before it died). Relaunched directly in the main session;
completed 2026-08-25 15:33.

**Final: PASS 4,656 / WARN 133 / ERROR 25 / SKIP 0 — of 4,814 total.**

WARN = a real issue but already downgraded to non-blocking severity in the
test config (mostly `not_null` checks on known-messy source fields — treasury
debt-to-penny, slave-trade voyage records, WPA slave narratives, European
Court of Human Rights case dates, military spending codes, plus some registry
vocabulary drift). Not new, not blocking, already accepted risk.

**ERROR = 25 real, unaccepted failures.** Breakdown:

- **13 are duplicate-row / grain violations** — a column combination the
  model assumes is unique (like "one row per country per year per trade
  flow") turns out not to be, across a wide mix of sources: international
  trade-flow data, EPA air-permit programs, EPA water monitoring, an EPA
  enforcement-case table, an SEC money-market-fund table, two CDC health
  survey tables, a CMS opioid-treatment-provider table, a conflict-events
  table, an FTC case-actions table, a federal courts stats table, a missile-
  test-events table, and a web-archive-crawl table.
- **7 are `not_null` failures** — a field that's supposed to always be
  filled in is blank somewhere: an IRS zip code field, a foreign-agent
  registration number, an OFAC sanctions-entity number, a tribal-geography
  object ID, a UK company-registry number, plus the 2 OSHA ones below.
- **4 are uniqueness failures** — an ID that's supposed to be one-per-thing
  isn't: an EPA water-permit violation ID, an EU legal-document ID, a police-
  violence-incident ID, a Congress member ID.
- **2 are OSHA, and they're a different kind of failure entirely** — not bad
  data, a **missing staging view**. The landing table exists (and is
  actively being re-loaded right now) but nobody ever built the cleanup
  layer on top of it, so these two tests couldn't even run — they errored on
  "object does not exist," not on bad values. This is the exact same defect
  already flagged in `build-state.md` ("242 sources have no staging view at
  all") — OSHA is one of the 242, now individually named.
- **1 is a custom platform-health check** (`assert_ripple_timeline_registry`)
  — needs its own look, not diagnosed further here.

None of these 25 overlap with the already-known trap list in
`honesty/traps.py` — they're genuinely new findings from this run, not
re-discoveries.
