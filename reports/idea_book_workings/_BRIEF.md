# Extraction brief — The Idea Book

Chris's words, verbatim: "I want you to organize all of these into an easy to read,
understand, and reference, singular source. We are going to call it 'The Idea Book'"
and "I want no information or ideas lost, but I dont want redundancy — merge and
refine where you can."

Your job: read EVERY file assigned to you, fully, and write ONE markdown file with
every idea, method, rule, lens, and finding in it. Nothing lost. Do not query the
warehouse. Do not summarize sections — extract items.

## Output shape — one table per kind

Write to the path you are given. Use these sections, each a markdown table.
Skip a section only if your files hold nothing of that kind.

### IDEAS  (a question the data could answer, a hunch, a wonder, a wow idea, a docket line)
| id | idea, one plain line | subject | tables or hubs named | join key | picture | status or result | source file § section |

- id = your family prefix + running number, e.g. TB-001, WN-001, HD-001, LB-001, LF-001
- status: found / dead / open / probed / not checked — plus the one-line result if any
- if the same idea appears twice in YOUR files, one row, both sources in the last column
- keep numbers exactly as written in the source; never round, never invent

### METHODS  (a posture, verb, lens, move, technique, viz method, grading scheme)
| id | name | what it is, plain | when to use it | source |

### RULES  (a key rule, standing rule, trap-shaped constraint, verification check)
| id | rule, plain | why | source |

### FINDINGS  (a result that was actually run and survived, with its number)
| id | finding | number | tables | source |

### DEAD ENDS  (things tried that failed, and why)
| id | what was tried | why it died | source |

### LOOSE  (anything that fits nowhere above — quotes, framing, glossary words)
| id | item | source |

## Rules
- BAR SPEAK: plain words, short. Compress by word choice, never by omission.
- Every row cites its source file and section heading.
- Table cells are fragments. No sentences over 20 words.
- At the top of your file: a count of rows per section and the list of files you read with line counts.
- If a file is huge, read it in chunks; do not stop early.
