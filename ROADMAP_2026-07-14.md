### 3.1 What's already standing (all verified this session)

The stack already contains, working: a guarded read lane (`viz/sqlrun.py` — text guard, claim-table block, lane verification at connect, 300s timeout, 10k row cap); a chart engine with inference + save-as-card (`viz/plugs.py`, `viz/card.py`); a fact/lead classifier + badge (`viz/safety.py`); catalog discovery (`viz/catalog.py`); a Streamlit shell exposing all of it (`serve/serve_workbench.py`, already routed inside `serve/app.py` — receipts `serve/app.py:111,414-416`); an entity-thread engine (the Dossier over the 9.8M spine — coded and routed; not exercised live this session); and a pre-aggregation pattern (`LIBRARY_MARTS.PUBLIC.*_AGG`, built dbt-free by `scripts/build_giant_aggs.py`). **The missing 20% is one visible thing — today you must type SQL — plus two named plumbing gaps (v2): `sqlrun.run()` takes no bind parameters, and the badge engine classifies SQL text, not registry grades.** Everything else downstream of the query string exists.

### 3.2 The app: three options

**Option A — extend `serve/app.py`: add a Compose view beside the Workbench.** *(RECOMMENDED)*
- **How:** new `serve/serve_compose.py`: measure picker → group-by → filter chips → chart-type override → renders through the same `plugs`/`safety`/`sqlrun` path the Workbench uses. Compose builds SQL from the registry (values via binds); the Workbench keeps existing for raw-SQL days; both save cards.
- **Pro:** ~90% reuse; one app, one budget; firewall and card model come mostly free; the four core views already have a SiS path.
- **Con:** Streamlit reruns whole-script per widget — cross-filter is "click → rerun → requery," BI-feel not Figma-feel. Known landmines from this codebase's own patterns (v2): `goto()` clears query params, so Compose state lives in `session_state` (deep-linking a composed view is extra work); widget keys must be per-measure or values bleed across switches; stashed DataFrames × N charts grow memory; the `sqlrun` module singleton has no thread lock (unlike `serve_session._LOCK`) — a double-click rerun can interleave cursors. All discipline, none refactor.
- **Best if:** one user, day-job hours, honesty rails mandatory. That's this project.

**Option B — greenfield Dash app.** Out of bounds per the brief unless A can't work — and A demonstrably can (the Workbench runs today; Compose is additive). Dash buys finer callbacks at the price of a second app, a second auth story, re-implementing the guard hooks, and no SiS path. **Rejected.**

**Option C — evidence.dev as the exploration UI.** Wrong tool: static build-time pages — exactly right for published pins (Phase 4a), exactly wrong for ad-hoc exploration. **Rejected for the Atlas; kept for the ceiling.**

### 3.3 The measure layer: three options

**Option 1 — full semantic layer (dbt metrics / MetricFlow).** Industry-standard, but a heavy YAML surface for one person, a layer that has churned across dbt majors, and overkill when the marts are already "final, analytics-ready, wide, denormalized" (Constitution's words). **Not this.**

**Option 2 — no layer: marts + raw SQL.** That's the Workbench today. Fails the north star (you must type SQL) and fails measure-level honesty. **Insufficient.**

**Option 3 — thin committed registry: the marts ARE the measures; the registry is the governance.** *(RECOMMENDED)*
A single reviewed file (**PROPOSED** `viz/measures.py` or YAML), each entry:

```
excluded_but_billing_dollars:
  sql:        SUM(ACTIVITY_TOTAL_USD)          # over a named mart or safe view
  source:     <fact-grade mart / V_LEADS_PUBLISHED-derived view>
  grain:      provider
  dims:       [STATE, YEAR, PAYER]             # only declared dims are offered
  provenance: lead                              # fact | lead | unverified — §3.5
```

- **Harm-lens enforcement, made concrete (v2 — v1 claimed this without designing it):** `harm_lens` is **required non-empty for every headline measure and rendered on every chart** (subtitle line, embedded in saved cards). ### 3.4 Cross-filtering on wide marts (don't pretend it's free)

The marts are deliberately wide/denormalized — the opposite of the star schema BI cross-filtering assumes. The bridge, using only what exists:

- **Conformed dimensions we actually have:** geography (STATE/FIPS — `CORE.DIM_TRACT`, `XWALK_ZCTA_COUNTY`), time (`CORE.DIM_DATE`), and **entity** via the connect spine + `JOIN_KEYS_STD` (NPI/EIN/CIK/CCN/IMO…).
- **The honest rule (PROPOSED):** each registry entry *declares* its dims. Cross-filtering operates only on dims shared by the charts on screen; a filter a mart can't honor greys out instead of silently no-op'ing. Global entity-level cross-filter is **not** a v1 promise — entity questions route to the Dossier (one click from any chart carrying a hard ID), which is the tool built for that. Spine tables stay behind the claim-table guard (§2 Phase 3a rule).
- State+year cross-filtering across health and politics works day one; "filter everything by this hospital" is a Dossier jump, not a fake pivot.

### 3.5 Honesty at the measure level (the part `sqlrun` can't do alone)

`viz/sqlrun.py` classifies SQL *text* — a name-only join buried upstream in a mart defeats it. So honesty moves into the registry, at build time, on **three axes** (v2 adds the second and hardens the first):

- **Provenance — machine-checked, not agent-asserted (v2):** a mart earns **fact-grade** only if a mechanical walk of its dbt lineage shows exclusively hard-ID joins back to landing; anything else — name-joins upstream, `LEADS` ancestry, un-walkable lineage — **fails closed to lead/unverified**. Agent judgment is never the certifier (an agent grading a mart "fact" is the AI vouching for the AI — the trust doctrine forbids exactly that). Every measure inherits the **weakest provenance of everything it touches**; the composer **refuses to emit SQL blending fact-grade and lead-grade rows into one scalar** — refusal at compose time, not a badge after the fact.
- **Freshness/trap (v2 — v1 had no axis for "fact-grade but poisoned"):** the registry carries the standing trap policies (`trap_ais_snapshot`, `trap_open_payments_split`, `trap_leie_npi_and_dates`, …). A measure over a trap-flagged source is badge-blocked or ships with the trap text on the chart — a clean-looking chart over the stale AIS snapshot would be *worse* than trivia; it would be a confident lie inside the truth instrument.
- **Badges:** rendered via `viz/safety.py`, with **registry grade taking precedence over text-classification** (v2 — the text path alone would stamp a confirmed-pins measure "unreviewed" and pass a lead-ancestry mart clean; receipt `safety.py:40`). Saved cards embed the badge line exactly as the Workbench does today.
