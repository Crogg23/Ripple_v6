## TRIAGE SHORTLIST — fix these first

1. **[CRITICAL] Heartbeat can double-run against a zombie child** (`scripts/heartbeat.py:493-504,587,397-407,916-921`).
   If `taskkill` fails or times out, both exceptions are swallowed and `_kill_group` returns
   True unconditionally — the tier logs `timeout_killed` for a child that is still alive. On
   Windows the lock is the pidfile fallback and records only the *heartbeat's* PID, so the next
   hourly tick sees a dead PID, reclaims the lock, and spawns a second `connect-changed` /
   loader **concurrently with the zombie** — two writers doing DELETE+INSERT reslices on the
   same `SPINE_KEYSET_LIVE` / `CONNECT_EDGES_INC` partitions. Rated CRITICAL (up from the audit
   pass's HIGH) because the outcome is concurrent-writer corruption of the spine; the trigger
   (a failed kill) is rare but entirely silent when it happens.
   **Fix:** verify with `p.poll()` after the wait and report `kill_failed` (not `timeout_killed`);
   persist the *child* PID in the lock/state and refuse lock reclaim while that PID is alive.

2. **[HIGH ×2] STEEL override keeps garbage edges** (`connect/discover.py:115-117`).
   Verified by execution. (a) The bypass applies to tier STRONG too, which includes `DOCKET` —
   docket numbers are court-local (`1:20-cv-00001` exists in every district), so cross-court
   collisions the collision gate used to kill now survive at confidence 0.4.
   (b) For big-table pairs, 3 shared values out of millions now form a permanent edge — and the
   `pad` normalizer accepts sentinel junk (`'PENDING'` → `'00PENDING'` as a "valid" EIN), which
   is exactly the NPPES/FCC-ULS masked-EIN trap. `confidence('EIN', a=5M, b=2M, matched=3)` →
   kept at 0.4; the old gate demanded 50,000. The collision gate was the *only* defense against
   sentinel/typo overlap between large tables, and the override removes it with no floor.
   **Fix:** restrict the bypass to tier STEEL only; require `matched >= 25` or `cover >= 0.01`
   before skipping the collision gate; log every edge kept *only* because of the override.

3. **[HIGH] CONNECT_EDGES replace is non-atomic and failures are swallowed**
   (`connect/store.py:72-98`, caught-and-printed at `connect/discover.py:297-298`).
   TRUNCATE then chunked INSERTs, autocommit, no transaction; any mid-write failure leaves the
   table empty/partial and the only trace is a stdout line. Every SQL consumer of the graph
   silently sees a wrong edge list until the next discover run.
   **Fix:** write to `CONNECT_EDGES__STAGING` + `ALTER TABLE ... SWAP WITH` (the loadkit pattern
   already in this repo), or BEGIN/COMMIT like `connect/calibrate.py:192-205`.

4. **[HIGH] Pour-path landing loads write the live table chunk-by-chunk**
   (`library-onboarding/ingest.py:591-666`, `_load_landing_chunked`).
   First chunk `overwrite=True`, then appends — a session/PAT death mid-stream leaves the live
   landing table half-written, and the freshness ledger COUNTs the partial as real. Self-heals
   only if re-run. (The bulk loaders are already safe: staging + SWAP.)
   **Fix:** land into `__STAGING` + SWAP like `loadkit/atomic_load.py`; keep the preflight PAT
   gate on every long loader entrypoint.

5. **[MEDIUM cluster] Reconcile drift-masking** (`scripts/heartbeat.py:683,705-711,866`).
   Stage 4 runs `connect seed` *without* `--reseed`, so if spine's internal twins-sync failed
   (swallowed to a `[warn]`, stage still rc=0) the stale twins are not repaired but every
   watermark + config sentinel is re-pinned over them; separately, `ok_twins_unverified` is
   counted as success by `_advance`, so a silently failed seed doesn't retry for 7 days.
   **Fix:** use `seed --reseed` in the staged path; treat `ok_twins_unverified` as non-success.
